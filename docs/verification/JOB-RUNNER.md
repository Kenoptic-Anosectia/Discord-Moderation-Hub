# JOB-RUNNER - async runner for the durable job queue (KJ2)

`src/jobs/runner.rs` runs the jobs of `queue.rs` (K02). The sync queue is bridged with `tokio_rusqlite::Connection::call` (SQL runs on the connection's own thread, never on the executor); handlers run as tokio tasks in a `JoinSet`. API: `Registry::register(kind, RestartPolicy, async fn(ClaimedJob) -> Result<(), HandlerError>)`, `Runner::new(db, Arc<impl Clock>, Registry, RunnerConfig)`, `Runner::start() -> Started` (runs `reconcile_after_restart` once, before any claim; `Started::report()` is for the caller to log), `Started::run() -> RunSummary`, `WakeHandle::wake()`, `ShutdownHandle::trigger()`, `Clock {now, sleep, sleep_until}` with `SystemClock`.

## Rules enforced (each has a test)
1. One source of truth: the registry's per-kind `RestartPolicy` is the table `reconcile` uses. A kind not registered is abandoned and reported at restart, and failed with `no_handler` at claim (terminal at once, no retry; a later deploy that adds the handler will not revive it).
2. At most `concurrency` handlers in flight (`1..=16`, `MAX_CONCURRENCY`; `Runner::new` refuses others). Claims ask for only the free slots; the claim loop does not sleep while a claim keeps changing rows.
3. Handler `Err(code)` -> `fail` with the queue's backoff, `failed` after `max_attempts`. Return `Err` only when the effect did not happen. A panic is caught per task (`handler_panicked`) and the runner goes on; a panic on an `AtMostOnce` kind is terminal (effect may have happened), on `RunAgain` it is retried.
4. Handler timeout: every handler runs under `handler_timeout`, timed by the injected `Clock::sleep` (fake clock in tests). When it expires the handler future is dropped and the job is treated as a cancel: `AtMostOnce` -> terminal `failed` with `handler_timed_out` (the effect may have happened, never run again); `RunAgain` -> `fail` with the queue's backoff and the same code. The slot is free again at once, so N hung handlers cannot starve the other jobs: a job can be `running` while the runner is up only until its timeout (the liveness test enforces exactly that).
5. Nothing due: sleep until the next pending `due_at`, but at most `max_poll`, or until `WakeHandle::wake()`. The wake is `Notify::notify_one` (a permit is kept if the runner is not waiting; not separately tested). Time is injected; `sleep_until` takes an absolute deadline. A due job that cannot be claimed (another claimer won it) is looked at again one second later, never in a tight loop (test: a trigger makes every claim lose, frozen clock, one sleep). Database errors on claim or acknowledgement: retried after a 1 s sleep. A result that cannot be written is kept and retried; on shutdown it is listed in `left_running`. An acknowledgement the queue refuses (the job was no longer `running`) is counted in `RunSummary::refused_acks`.
6. Shutdown: stops claiming, waits `shutdown_grace` for in-flight handlers, writes their results, then aborts the rest. Their jobs stay `running` (`RunSummary::left_running`, ids) and the next `start` reconciles them: `RunAgain` runs again, `AtMostOnce` is abandoned and reported. Shutdown takes at most `shutdown_grace` plus the time to write the acknowledgements; `shutdown_grace` is validated (below), so that bound is enforced.
7. Errors, `RunSummary` and `last_error_code` carry stable codes and job ids only. `HandlerError` holds a `&'static str`, so a handler cannot put runtime text into it; a code that is not `[a-z0-9_]{1,48}` is stored as `invalid_error_code`.

## Parameters for the wiring card (the runner reads no config keys)
`RunnerConfig::DEFAULT`: `concurrency` 4 (`1..=16`), `max_poll` 30 s (`1 s..=1 h`), `shutdown_grace` 10 s (`1 s..=300 s`, `MIN_SHUTDOWN_GRACE`/`MAX_SHUTDOWN_GRACE`), `handler_timeout` 60 s (`1 s..=1 h`, `MIN_HANDLER_TIMEOUT`/`MAX_HANDLER_TIMEOUT`), `retry` = `RetryPolicy::DEFAULT` (30 s base, 600 s cap, 5 attempts). Invalid values make `Runner::new` return a stable error (`invalid_concurrency`, `invalid_poll`, `invalid_shutdown_grace`, `invalid_handler_timeout`, `invalid_retry_policy`): W1 should log it and leave the feature off. W1 must call `wake()` after each `schedule`, call `shutdown_handle().trigger()` on exit, and surface `report().abandoned()` to staff. A handler must be able to finish inside `handler_timeout` (keep each kind's work short) or it will be cut and retried or failed.

## NOT done / limits
Not called from `main.rs`, no command, no config key, nothing switched on. No lease. Abort (the handler timeout, and the abort at the grace limit) drops a handler only at its next `.await`: a handler that blocks without awaiting (CPU loop, blocking call) can neither time out nor be stopped; it holds its slot and its worker thread and keeps running after shutdown. Handlers must not block; use async I/O or `spawn_blocking`. The default panic hook still prints a handler's panic message to stderr. The next-due lookup is one read-only `SELECT MIN(due_at)` issued by the runner because `queue.rs` has no such call. Tested with one connection per runner; two live runners on one file are not supported (reconcile has no lease). `max_poll` bounds only how late an unannounced job is noticed.
