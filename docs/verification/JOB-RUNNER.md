# JOB-RUNNER - async runner for the durable job queue (KJ2)

`src/jobs/runner.rs` runs the jobs of `queue.rs` (K02). The sync queue is bridged with `tokio_rusqlite::Connection::call` (SQL runs on the connection's own thread, never on the executor); handlers run as tokio tasks in a `JoinSet`. API: `Registry::register(kind, RestartPolicy, async fn(ClaimedJob) -> Result<(), HandlerError>)`, `Runner::new(db, Arc<impl Clock>, Registry, RunnerConfig)`, `Runner::start() -> Started` (runs `reconcile_after_restart` once, before any claim; `Started::report()` is for the caller to log), `Started::run() -> RunSummary`, `WakeHandle::wake()`, `ShutdownHandle::trigger()`, `Clock {now, sleep, sleep_until}` with `SystemClock`.

## Rules enforced (each has a test)
1. One source of truth: the registry's per-kind `RestartPolicy` is the table `reconcile` uses. A kind not registered is abandoned and reported at restart, and failed with `no_handler` at claim (terminal at once, no retry; a later deploy that adds the handler will not revive it).
2. At most `concurrency` handlers in flight (`1..=16`, `MAX_CONCURRENCY`; `Runner::new` refuses others). Claims ask for only the free slots; the claim loop does not sleep while a claim keeps changing rows.
3. Handler `Err(code)` -> `fail` with the queue's backoff, `failed` after `max_attempts`. Return `Err` only when the effect did not happen. A panic is caught per task (`handler_panicked`) and the runner goes on; a panic on an `AtMostOnce` kind is terminal (effect may have happened), on `RunAgain` it is retried.
4. Nothing due: sleep until the next pending `due_at`, but at most `max_poll`, or until `WakeHandle::wake()`. The wake is `Notify::notify_one` (a permit is kept if the runner is not waiting; not separately tested). Time is injected; `sleep_until` takes an absolute deadline. Database errors on claim or acknowledgement: retried after a 1 s sleep. A result that cannot be written is kept and retried; on shutdown it is listed in `left_running`.
5. Shutdown: stops claiming, waits `shutdown_grace` for in-flight handlers, writes their results, then aborts the rest. Their jobs stay `running` (`RunSummary::left_running`, ids) and the next `start` reconciles them: `RunAgain` runs again, `AtMostOnce` is abandoned and reported.
6. Errors, `RunSummary` and `last_error_code` carry stable codes and job ids only. `HandlerError` holds a `&'static str`, so a handler cannot put runtime text into it; a code that is not `[a-z0-9_]{1,48}` is stored as `invalid_error_code`.

## Tests (26 in `runner.rs`, files under `target/kj2-tests/`)
Due order with ties and the `due_at == now+1` boundary, backoff 30/60 s then `failed`, unknown kind, malformed payload/kind rows, panic (text not in the summary), at-most-once panic, concurrency 1/2/5 reaches and never exceeds N (12 jobs, multi-thread runtime), empty queue (fake clock: no wake-ups until time moves), exact sleep-until-due, wake vs no wake, shutdown with a stuck handler then restart (file DB), shutdown inside the grace period, a failed acknowledgement retried (SQL trigger), DB closed -> `db_closed`, registry kinds == queue kinds, config bounds, and a liveness test (12 seeded LCG runs x 40 steps: schedule, ok/flaky/fail/panic/hang handlers, restarts; ends with every job terminal, every abandonment reported, the at-most-once hang and panic kinds ran exactly once).
RED: `538df5e` (stubs + 26 tests): 24 failed, 2 passed (error codes and `SystemClock`, which were real in the stub). After GREEN, test-side races were fixed with no assertion weakened: waits on `pending` that was also the pre-claim state, a fake-clock wake that raced the runner (fixed by making the idle sleep an absolute deadline), and the liveness model, which now advances time when no wake was sent. Mutations tried, each made tests fail: claim limit `free+1`; at-most-once panic retried; idle sleep shortened; poll cap removed; reconcile table all `RunAgain`; failed acknowledgement dropped; grace ignored.

## Parameters for the wiring card (the runner reads no config keys)
`RunnerConfig::DEFAULT`: `concurrency` 4, `max_poll` 30 s (1 s..=1 h), `shutdown_grace` 10 s, `retry` = `RetryPolicy::DEFAULT` (30 s base, 600 s cap, 5 attempts). Invalid values make `Runner::new` return a stable error: W1 should log it and leave the feature off. W1 must call `wake()` after each `schedule`, call `shutdown_handle().trigger()` on exit, and surface `report().abandoned()` to staff.

## NOT done / limits
Not called from `main.rs`, no command, no config key, nothing switched on. No lease: a handler aborted at the grace limit is dropped only at its next `.await` (blocking code inside a handler keeps running). The default panic hook still prints a handler's panic message to stderr. The next-due lookup is one read-only `SELECT MIN(due_at)` issued by the runner because `queue.rs` has no such call. Tested with one connection per runner; two live runners on one file are not supported (reconcile has no lease). `max_poll` bounds only how late an unannounced job is noticed.
