# MANAGED-EMBEDS - managed embed posts (pure core)

Card EM1. Module `src/embeds/{mod,template,posts}.rs` - pure, Discord-free core. This card IS the persistence card for the `managed_posts` table.
`embeds::template::load(&str) -> Result<EmbedTemplate, TemplateError>` loads one embed template from JSON, checks it against the Discord embed limits and returns it trimmed. `EmbedTemplate::content_hash()` is the SHA-256 hex digest of the canonical form of the PARSED template, so the JSON key order of the source file cannot change it. `embeds::posts::plan(&PlanRequest) -> Plan` decides create / edit / no-op / recreate / refuse. `embeds::posts::{migrate,get,upsert,apply,list,delete}` read and write the `managed_posts` row. No serenity type, no clock read, no randomness; `now` is a parameter and every id is passed in.

Rules it enforces:
- Same template twice -> `NoOp` (reposting would spam the channel). Changed template -> `Edit` of the SAME recorded message, never a new post.
- A recorded message reported missing -> `Refuse(missing_message)`, or `Recreate` only when the caller passes the explicit allow-recreate flag (a deleted rules post may be deliberate). A key recorded for another channel or another guild is refused; the allow-recreate flag does not lift that refusal.
- An unusable key (empty, >64 bytes, a path separator, `..`, a leading dot, or any character outside `[A-Za-z0-9._-]`) and a template hash that is not 64 lowercase hex characters are refused before anything else is decided.
- Limits, inclusive, measured in characters after trimming: title 256, description 4096, 25 fields, field name 256, field value 1024, footer text 2048, author name 256, and a combined total of 6000 over title + description + every field name + every field value + footer text + author name. An unknown JSON key, a non-object document, a colour above 0xFFFFFF and a template with no content are refused too.
- Every error and refusal is a stable code. No error, `Display` or `Debug` output ever contains template text, a field name or a value.

Config keys (read by the wiring card, not by this module), default then safe failure: `EMBED_TEMPLATE_DIR` unset, unset => the feature is off and no template is loaded; this module reads no environment variable and no file.

Tested (54 unit tests in `src/embeds/{template,posts}.rs`): the General and NSFW rules embeds rebuilt from `YAG:199-248` load within the limits (the NSFW one is 5 fields, 3458 characters in total, every field value under 1024); each limit at and one past the boundary; the total counted over every part; whitespace trimmed before measuring; empty text normalised to absent; the ten error codes distinct and stable; no template text in an error; the hash 64 hex characters, stable across JSON key order, changed by content, by field order and by colour; the canonical form unambiguous; the planner create / no-op / edit-same-message / missing-refused / missing-recreate / key-reuse cases, plus the allow-recreate and invalid-key and invalid-hash refusals; the planner pure; the migration idempotent; the repository round trip, replace, survive-reopen, ordered list, delete, corrupt-id, corrupt-hash and zero-id reporting, and the plan guarding the write. RED evidence: commit `bf8de90` ran this suite against a non-functional scaffold - `test result: FAILED. 9 passed; 43 failed` (the 9 were the error-code tables, the error-hygiene checks, the trivially pure planner and three stub behaviours that happen to match). Mutation evidence: 23 one-condition mutations, each caught by a named test - the two that survived round one (a stored id of zero, the canonical form's field order) got their own tests.

NOT done here: no runtime (nothing posts, edits or schedules); no Discord registration, no commands, no event wiring, no `.env`/`config.rs` change; the module reads no environment variable and no file; no rendering to a serenity `CreateEmbed` (the wiring card EM2 builds that); the module-level `#![allow(dead_code)]` in `src/embeds/mod.rs` is temporary and W1 removes it.
