# WELCOME-RENDER - welcome template and renderer (pure)

Card WE1. Module `src/welcome/{mod,render}.rs` - pure, Discord-free core.

`welcome::render::WelcomeTemplate::load(&str, &IdMap)` parses and validates one JSON template (one embed plus optional content). `welcome::render::welcome_policy(&WelcomeTemplate, &MemberContext, &IdMap) -> SkipReason` decides whether a joining member is skipped. `welcome::render::render_welcome(&WelcomeTemplate, &MemberContext, &IdMap) -> RenderedWelcome` fills the placeholders and returns plain data (content, embed title/description/fields/footer/author). No serenity type, no I/O, no clock read, no randomness; every id, the member count and the server name are passed in.

Rules it enforces:
- An unknown placeholder, an unknown `{channel:KEY}` / `{role:KEY}` key, a malformed key and an unbalanced brace are refused when the template is LOADED, never when a member joins. A `{}` with an unknown JSON key is refused too. `{user_mention}`, `{username}`, `{server}`, `{member_count}`, `{member_ordinal}` (1st, 2nd, 3rd, 11th, 12th, 13th, 21st, 111th ...), `{channel:KEY}`, `{role:KEY}`.
- The untrusted `username` is stripped of zero-width and bidi control characters, capped at 64 characters, escaped against Discord markdown and neutralised against mention syntax (`@` becomes the full-width `＠`, `<` and `>` become `‹` and `›`) before it is placed anywhere. `{user_mention}` is the only way a user mention is produced; `{channel:KEY}` and `{role:KEY}` carry an id from the caller's map, so the only id the renderer emits is the joining user's own id and the ids the caller put in the map. The other caller-supplied texts (`{server}`, `{member_count}`) are copied through unchanged: the server name is the server's own name and is not an id this module chooses.
- The Discord embed limits are enforced at load and count characters, not bytes: title 256, description 4096, at most 25 fields, field name 256, field value 1024, footer 2048, author name 256, 6000 characters in total (title + description + every field name and value + footer + author). The message content limit is 2000 characters. An empty field name or value is refused.
- A bot member is skipped (`SkipReason::Bot`); a human is `SkipReason::None`. The old YAGPDB command welcomed bots as well; that is deliberately not copied.
- The id map keeps channels and roles apart, refuses the id zero and a key that is not a plain word, and keeps the first id inserted for a key.
- Errors are stable enum codes (`TemplateErrorKind::code()`); they never carry template text, a user name or an id.

Config key (read by the wiring card, not by this module): `WELCOME_TEMPLATE_PATH`, default unset. Unset means the welcome feature is off. The required safe failure for the wiring card: a path that cannot be read, or a template that fails to load, must leave the welcome unposted and the startup message must name the key, never the template text. This module reads no environment variable and no file, so it enforces none of that itself.

Tested (62 unit tests in `src/welcome/render.rs`): the example template loading and rendering with no leftover placeholder; every placeholder substituted; the ordinals including the teens and the 100/1000 boundaries; an unknown placeholder, an unknown channel key and an unknown role key refused at load; a hostile key refused at load (empty, space, dash, dot, slash, a path, a `file://` URI, a `$(...)` shell fragment, a non-ASCII letter, a brace, a wrong kind of thing and a doubled prefix) and an unbalanced or doubled brace refused at load; the unknown JSON field refused; the username escaped against markdown, `@everyone`/`@here`, user and role mention syntax, zero-width and bidi controls, capped at 64 characters by characters not bytes, and escaped in every place it can appear; every embed limit at its exact value (256/257, 4096/4097, 25/26 fields, 1024/1025, 2048/2049, 6000/6001) and the multi-byte variant; the 2000/2001 content limit; the empty field name and value; the bot skipped and the human not skipped; the id map rules; the error-code table, the error text carrying no template text, and the error being a `std::error::Error`. RED evidence: commit `587fdfe` ran this suite against a non-functional scaffold - 11 passed, 51 failed (the 11 were already satisfied by the type definitions alone).

Mutation evidence (each mutation was applied to the implementation, the suite re-run, and the change reverted): removing the `@` neutralisation failed `username_at_everyone_is_neutralised` and `username_is_escaped_in_every_place_it_can_appear`; dropping the teens rule in `english_ordinal` failed `member_ordinals_are_correct`; removing the unknown-key check failed `unknown_channel_key_is_refused_at_load` and `unknown_role_key_is_refused_at_load`; changing the total limit to `>=` failed `total_embed_limit_is_exact`; never skipping bots failed `bot_member_is_skipped` and `bot_is_skipped_before_rendering`; keeping one zero-width character failed `username_control_characters_are_stripped`; making `escape_markdown` the identity failed `username_markdown_is_escaped` and `username_is_escaped_in_every_place_it_can_appear`; raising the username cap to 1000 failed `username_length_is_capped` and `username_cap_counts_characters_not_bytes`.

NOT done here: no runtime (nothing posts a welcome, grants a join role or reacts to a join event); no Discord registration, commands, event wiring or `.env`/`config.rs` change; no persistence and no database table; the join roles are the role-service card's work, not this card's; the module-level `#![allow(dead_code)]` in `src/welcome/mod.rs` is temporary and W1 removes it.
