# VOICE-ROOMS - temporary voice room policy (pure)

Card VR1. Module `src/voice_rooms/{mod,policy}.rs` - pure, Discord-free core, no serenity type, no I/O, no clock read, no randomness; `now` and every id are passed in.

## Rules enforced
- **Hub join creates a room** (`decide_join`): only a join in the hub channel of the configured guild, by a non-zero user id, and only under the per-user cap, the global cap and the per-user cooldown. Each refusal carries a stable code (`per_user_cap_reached`, `global_cap_reached`, `create_cooldown`, `not_hub_channel`, `invalid_user_id`, `guild_mismatch`).
- **Name sanitising** (`sanitize_name`): the cleaning runs in a fixed order - the invisible characters FIRST, then the mentions until the text stops changing, then the links. Removing the invisible characters first is what stops a zero-width character from hiding a mention from the mention pass. The mention pass has NO fixed pass count: every pass that changes the text removes at least one character, so the text strictly shrinks and the loop ends, and the bound used is the number of characters in the text - the number of passes it can need. A fixed count would be a bound the caller controls, and a mention nested deeper than it came back as a live token. The invisible set is the Unicode **default ignorable** class plus the **blank** fillers, named in `is_default_ignorable` and `is_blank`: the format characters (zero-width U+200B-U+200F, bidi U+202A-U+202E, isolates U+2066-U+206F, U+061C, U+180E, U+00AD, U+2060-U+2064), the combining marks that join nothing (U+034F, U+17B4-U+17B5), the variation selectors (U+FE00-U+FE0F, U+E0100-U+E01EF), the musical format controls (U+1D173-U+1D17A), the interlinear annotation characters (U+FFF9-U+FFFB), the tag characters (U+E0000-U+E007F), the byte order mark, and the blank fillers (U+115F-U+1160, U+3164, U+FFA0, U+2800); the non-ASCII spaces go too, the plain ASCII space stays. A link is a class too: a segment whose host part (in front of the first slash, question mark or fragment marker, without the port and without the user information) is a dotted name whose last label is alphabetic or punycode is a host, so `example.com`, `example.com:8080/x`, `example.com?x=1`, `example.com.`, `(example.com)`, `www.x.y`, `example.xn--p1ai` and `discord.gg` are removed, as are URLs, invite hosts and an invite host spread across spaces (`discord . gg/x`). Shortens to at most 100 characters (characters, not bytes) and falls back to the default name when nothing is left.
- **Overwrite plan** (`build_overwrites`): the category's overwrites plus one owner overwrite. The owner's allow set is the constant `OWNER_RIGHTS` (connect, speak, move, mute); the deny set is `FORBIDDEN_OWNER_RIGHTS` (manage roles, manage channels, administrator). No input can widen the owner rights.
- **Permit** (`decide_permit`): refused when the member could not already view the category, when a member id is zero, when the requester does not own the room, when the member is the owner themself, and in a channel the policy does not track.
- **Leaving** (`decide_leave`) and the **sweep** (`decide_sweep`): `Room::occupants` is the count BEFORE the leave, so the member who is leaving is still counted. A room whose count is one is empty once that member leaves and takes the grace path; only a room whose count is two or more still holds members afterwards, and then the owner leaving it makes it `Claimable` while anybody else is refused with `not_room_owner`. The grace check applies to whoever leaves last, so a room whose owner already left is still cleaned up. An empty room becomes `Cleanup` only once the grace period has elapsed. A channel the policy does not track is never deleted. The sweep is the runtime's periodic check for a room whose last member left before the grace elapsed, so nobody leaves it again: it has no leaver, so `occupants` is the current occupancy there, and it cleans an empty room up once the grace has elapsed, never touches an occupied room, never claims a room and never touches an untracked channel.
- **Rename budget** (`decide_rename`): counted per room inside its window; the budget is data, so the runtime enforces the same number. Discord's exact limit is not verified here.
- **Time is injected and never overflows**: every elapsed time uses `saturating_sub`, so an extreme value loaded from persistence can neither panic in a debug build nor wrap around in a release build. A negative grace period or a negative rename window is refused with `invalid_config` rather than honoured.

## Assumptions (Chai's behaviour is unknown; conservative where silent)
- The room name at creation is the configured default; `sanitize_name` is also the public entry point for a later rename command. The guild id is part of the configuration: a join from another guild is out of scope.
- The exact Discord rename limit is not verified; the budget is data with a default of 2 renames per 600 s. Discord retired `MANAGE_PERMISSIONS`, so serenity 0.12 has no constant for it; the escalating set is manage roles, manage channels and administrator, and the retired bit is named `LEGACY_MANAGE_PERMISSIONS` so it can be asserted on.
- The occupancy is the count BEFORE the leave, and the runtime owns both the count and the `empty_since` stamp; the policy reads them and never writes them.

## What is tested (113 unit tests in `src/voice_rooms/policy.rs`)
Hub join creates a room and each cap, the cooldown and the channel/guild/id checks deny; the cooldown boundary is allowed exactly at the limit; every sanitising case above, including a mention split by a zero-width character, a joiner or a control character, a mention nested 3, 18 and 64 levels deep and a sweep over every depth from 1 to 40, a name of only invisible or only blank characters, a host in brackets, a host with a comma, a trailing dot, a query, a fragment, angle brackets and a punycode top-level domain; the owner overwrite grants exactly the four rights and grants none of the escalating ones (the category's own overwrites are copied through unchanged, so what the server admin put there is what the room gets); the permit refusals; the occupancy boundary at exactly two members; owner leave -> claimable, empty -> cleanup only after the grace, the grace boundary, untracked channels never deleted; the sweep cleans an empty room up after the grace, never an occupied one, never an untracked one and never claims one; the rename budget, its per-room count, its window and the "never plans more renames than the budget" loop; the five extreme-timestamp cases; the negative grace and the negative rename window are refused; a seeded 2000-step join/leave sequence that asserts the global and per-user caps after every step and applies EVERY leave on every branch, and a second seeded sequence whose quiet phase drains the rooms through `decide_leave` with a non-owner, advances the clock past every grace and asserts that every room is actually GONE from the state.

## Config keys (READ by the wiring card, not by this module; this module reads no environment variable and no file)
`VOICE_ROOMS_MODE` (default `off`; any other value means off) | `VOICE_ROOM_HUB_CHANNEL_ID` (default unset; unset means no hub, so no room is ever created) | `VOICE_ROOM_CATEGORY_ID` (default unset; unset means no category, so no room is ever created) | `VOICE_ROOM_PER_USER_CAP` (default `1`; invalid or negative means 1) | `VOICE_ROOM_GLOBAL_CAP` (default `25`; invalid or negative means 25) | `VOICE_ROOM_CREATE_COOLDOWN_SECS` (default `30`; invalid or negative means 30) | `VOICE_ROOM_EMPTY_GRACE_SECS` (default `60`; invalid or negative means 60 - a negative grace would clean a room up the instant it became empty) | `VOICE_ROOM_DEFAULT_NAME` (default `Voice Room`) | `VOICE_ROOM_RENAME_BUDGET` (default `2`) | `VOICE_ROOM_RENAME_WINDOW_SECS` (default `600`; negative is refused by the policy as `invalid_config`, because a negative window would make the rename budget unlimited).

## What is NOT done
No runtime (nothing creates, deletes, renames or permits), no Discord registration, no commands, no event wiring, no persistence, no `.env` or `config.rs` change. The module-level `#![allow(dead_code)]` in `src/voice_rooms/mod.rs` is temporary and wiring card W1 removes it. The state (`VoiceRoomState`) is plain data the runtime owns; nothing here writes it. The occupancy count and the `empty_since` stamp are the runtime's to maintain: the policy reads them and never sets them, so a runtime that does not stamp `empty_since` never cleans a room up. Known limits of the host rule: it removes ordinary dotted words (`notes.txt`, `Mr.Smith` and `rock.and.roll` all become `party`), and a bare IP (`192.0.2.7/x`), a full-width or ideographic dot (`example．com`, `example。com`) and a spaced dot (`example . com`) all survive.
